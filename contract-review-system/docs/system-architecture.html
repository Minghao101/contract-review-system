1. LangChain 是什么

本项目使用 LangChain 生态的核心组件来构建 AI Agent 应用

LangChain Core

langchain-core

提供基础抽象层，本项目用到的：

  • BaseLLM — 所有 LLM 的抽象基类
  • SystemMessage / HumanMessage — 消息格式化
  • @tool — LangChain Tool 装饰器
  • BaseChatModel.ainvoke() — 异步调用 LLM
LangChain OpenAI

langchain-openai

OpenAI 兼容接口封装。本项目通过 ChatOpenAI 调用任何 OpenAI 兼容的 API（如 MIMO 的 Anthropic 接口）。

LangChain Anthropic

langchain-anthropic

ChatAnthropic — 原生 Anthropic Claude 集成。当前配置使用此接口调用 MIMO 模型。

LangChain Community

langchain-community

社区集成，本项目使用 Ollama LLM 连接器（本地模型回退方案）。

本项目怎么用 LangChain？
项目没有用 LangChain 的 Agent/Chain/AgentExecutor 高层抽象，而是： 1) 用 ChatAnthropic / ChatOpenAI / Ollama 作为 LLM 调用层 → 统一接口 2) 用 SystemMessage + HumanMessage 构建 prompt → 发送给 LLM 3) 用 self.llm.ainvoke(messages) 异步调用 → 获取结构化输出 4) 所有 Agent 调度、并行、路由逻辑全部手写在 CoordinatorAgent 中
llm_factory.py — LangChain LLM 创建
from langchain_core.language_models import BaseLLM from langchain_community.llms import Ollama from langchain_openai import ChatOpenAI from langchain_anthropic import ChatAnthropic class LLMFactory: def create_llm(self, provider=None): provider = provider or self.settings.LLM_PROVIDER if provider == "anthropic": return ChatAnthropic( # langchain-anthropic model=self.settings.LLM_MODEL, api_key=self.settings.LLM_API_KEY, base_url=self.settings.LLM_API_BASE, # MIMO 代理地址 temperature=self.settings.LLM_TEMPERATURE, max_tokens=self.settings.LLM_MAX_TOKENS, ) elif provider == "openai": return ChatOpenAI(...) # langchain-openai elif provider == "ollama": return Ollama(...) # langchain-community

3. LLM 工厂 — llm_factory.py

统一管理 LLM 实例，所有 Agent 通过 get_llm() 获取

src/utils/llm_factory.py
from langchain_core.language_models import BaseLLM from langchain_anthropic import ChatAnthropic class LLMFactory: def __init__(self): self.settings = get_settings() self._llm: Optional[BaseLLM] = None # 单例缓存 def create_llm(self, provider=None) -> BaseLLM: provider = provider or self.settings.LLM_PROVIDER if provider == "anthropic": return ChatAnthropic( model=self.settings.LLM_MODEL, # "mimo-v2.5" api_key=self.settings.LLM_API_KEY, base_url=self.settings.LLM_API_BASE, # "https://token-plan-cn.xiaomimimo.com/anthropic" temperature=self.settings.LLM_TEMPERATURE, # 0.3 max_tokens=self.settings.LLM_MAX_TOKENS, # 10000 ) # ... openai / ollama 分支类似 def get_llm(self) -> BaseLLM: if self._llm is None: self._llm = self.create_llm() # 懒加载 + 单例 return self._llm # 全局便捷函数 llm_factory = LLMFactory() def get_llm() -> BaseLLM: return llm_factory.get_llm()
设计要点：单例模式，整个进程共享一个 LLM 实例。切换 provider 只需改 config/settings.py 中的 LLM_PROVIDER。所有 Agent 基类自动调用 get_llm() 获取实例。

4. BaseAgent 基类 — base_agent.py

所有 5 个 Agent 的父类，定义统一接口和生命周期管理

src/agents/base_agent.py
from abc import ABC, abstractmethod from langchain_core.language_models import BaseLLM from src.utils.llm_factory import get_llm class BaseAgent(ABC): def __init__(self, agent_id, name, role, llm=None, description=""): self.agent_id = agent_id # "document_parser" self.name = name # "文档解析Agent" self.role = role # "document_parser" (用于 Coordinator 查找) self.llm = llm or get_llm() # 从 LLMFactory 获取实例 self.is_running = False self.private_memory = {} # 私有记忆字典 @abstractmethod async def process(self, task: Dict) -> Dict: """每个子类必须实现的处理方法""" pass def get_status(self) -> Dict: return { "agent_id": self.agent_id, "name": self.name, "role": self.role, "is_running": self.is_running, }
关键设计：self.llm 是 LangChain 的 BaseLLM 实例，子类直接调用 self.llm.ainvoke(messages) 即可与 LLM 交互。role 字段用于 CoordinatorAgent 根据执行计划查找对应 Agent。

coordinator_agent.py — LLM 规划执行计划
async def _plan_execution(self, task) -> List[Dict]: """用 LLM 生成执行计划""" system_prompt = """你是一个智能任务规划专家。根据可用的Agent，制定最优执行计划。 可用的Agent： {agent_descriptions} 输出格式（JSON数组）： [{{ "task_name": "任务名称", "agent_role": "agent角色", "depends_on": ["依赖的任务名"], "parallel": false }}]""" messages = [ SystemMessage(content=system_prompt.format( agent_descriptions=self._get_agent_descriptions() )), HumanMessage(content=f"合同类型: {contract_type}...") ] response = await self.llm.ainvoke(messages) # LangChain 异步调用 plan = parse_json_from_llm(response.content) # 解析 JSON return self._validate_plan(plan)
coordinator_agent.py — 并行调度 + 结果汇总
async def _execute_plan(self, plan, original_task, contract_text): results = {}; completed = set() task_map = {p["task_name"]: p for p in plan} while len(completed) < len(plan): # 找出依赖已满足的任务 ready = [name for name, info in task_map.items() if name not in completed and all(d in completed for d in info.get("depends_on", []))] # 并行执行就绪任务 async_tasks = [] for task_name in ready: agent = self._find_agent_by_role(task_map[task_name]["agent_role"]) task_input = self._prepare_input(task_map[task_name], original_task, contract_text, results) async_tasks.append(self._execute_single(task_name, agent, task_input)) task_results = await asyncio.gather(*async_tasks, return_exceptions=True) for (name, _, _), result in zip(ready, task_results): results[name] = result; completed.add(name) return results def _find_agent_by_role(self, role: str) -> Optional[BaseAgent]: """根据 role 字段查找已注册的 Agent""" for agent in self._registered_agents.values(): if agent.role == role: return agent return None
调度核心逻辑：while 循环不断找"依赖已满足"的任务 → asyncio.gather 并行执行 → 标记完成 → 继续下一轮。当所有任务完成（如 generate_report 依赖前4个），自动串行执行。

6. DocumentParserAgent — 文档解析

LLM 驱动的合同结构化信息提取，支持长文本 Map-Reduce

document_parser_agent.py — 核心处理逻辑
async def process(self, task: Dict) -> Dict: contract_text = task.get("contract_text", "") if len(contract_text) > self.chunk_size: # 12000 字符阈值 return await self._map_reduce_extract(contract_text) # 长文本分块 return await self._llm_extract_all(contract_text) # 短文本直接提取 async def _llm_extract_all(self, text, specified_type=None): """单次 LLM 调用提取所有信息""" system_prompt = """你是一个专业的合同信息提取助手。 输出格式（严格JSON）： {{ "basic_info": {{"title": "...", "parties": [...], "signing_date": "..."}}, "contract_type": "sales/service/lease/...", "sections": [{{"id": "1", "title": "...", "content": "...", "level": 1}}], "dates": [{{"raw": "...", "date": "YYYY-MM-DD", "type": "签署/生效/到期"}}], "amounts": [{{"raw": "...", "value": 数值, "currency": "CNY", "type": "总价/违约金"}}], "definitions": [{{"term": "术语", "definition": "定义内容"}}] }} 规则：金额统一为元，日期统一YYYY-MM-DD，只输出JSON""" messages = [SystemMessage(content=system_prompt), HumanMessage(content=f"请提取以下合同的信息：\n\n{text}")] response = await self.llm.ainvoke(messages) # LangChain 异步调用 content = extract_llm_content(response.content) # 处理不同响应格式 return parse_json_from_llm(content) # 容错 JSON 解析
Map-Reduce 长文本策略：超过 12000 字符时，按条款边界（"第X条"）语义分块 → 每块并行 LLM 提取 → 合并去重 → 输出统一结构。短文本直接一次 LLM 调用。

7. RiskAssessmentAgent — 风险评估

LLM 识别风险 + 量化评分 + 缓解建议生成

risk_assessment_agent.py — LLM 风险评估
async def _assess_with_llm(self, text, contract_type): system_prompt = """你是一个资深的合同风险评估专家。 输出格式（严格JSON）： {{ "risk_level": "low/medium/high/critical", "risks": [{{ "name": "风险名称", "severity": "high/medium/low", "category": "liability/termination/payment/ip/...", "description": "详细描述", "suggestion": "修改建议" }}], "recommendations": [{{"priority": "high", "suggestion": "...", "reason": "..."}}], "summary": {{"total_risks": 5, "high_risks": 2, ...}} }} 规则：识别无限责任、单方解除、自动续约、违约金过高、管辖权等风险""" messages = [SystemMessage(content=system_prompt), HumanMessage(content=f"请对以下合同进行风险评估：\n\n{text[:8000]}")] response = await self.llm.ainvoke(messages) result = parse_json_from_llm(extract_llm_content(response.content)) # LLM 失败时回退到正则匹配 if not result or not isinstance(result, dict): return self._assess_with_regex(text) # 检测"无限责任"、"单方解除"等关键词 result["risk_quantification"] = self.quantify_risk(result.get("risks", [])) result["mitigation_plan"] = self.suggest_mitigation(result.get("risks", [])) return result
风险量化算法：每个风险按 severity（high=3, medium=2, low=1）× category 权重（liability=1.5, payment=1.3, ip=1.4...）计算加权分数，归一化到 0-100 分。高/中风险自动生成缓解建议模板。

class ComplianceCheckerAgent(BaseAgent): # 各类合同的必备条款（硬编码规则） REQUIRED_CLAUSES = { "sales": ["标的物", "价款", "交付", "验收", "违约责任", "争议解决"], "service": ["服务内容", "服务期限", "服务费用", "验收标准", "违约责任", "保密"], "lease": ["租赁物", "租期", "租金", "维修责任", "违约责任", "终止条件"], "labor": ["工作内容", "劳动报酬", "工作时间", "社会保险", "劳动保护", "解除条件"], "nda": ["保密信息定义", "保密义务", "保密期限", "违约责任", "争议解决"], "general": ["合同标的", "价款报酬", "履行期限", "违约责任", "争议解决"], }

13. 三层记忆系统

私有记忆 → 会话记忆 → 长期记忆

PrivateMemory

私有记忆

BaseAgent.private_memory 字典。每个 Agent 独有，如文档解析 Agent 存储提取的结构化数据。生命周期 = Agent 实例。

ConversationContext

会话记忆

多轮对话上下文：对话历史、意图链、各 Agent 结果缓存。生命周期 = 一次会话。存储在内存中。

LongTermMemory

长期记忆

Qdrant 向量持久化：审查历史 + 用户偏好 + 知识积累。支持跨会话语义检索。
